# Sensor pixel fit (display-only, opt-in)

`SensorFitCard` is rendered only after `/api/fields/status` returns HTTP 200 with `enabled: true`. The server status route comes from F1 and requires `FIELDS_ENABLED=on`; no default Wrangler variable is added. Failures and timeouts hide the card. No geometry, counts, category, or threshold enters the planner, cache identities, or Field Watch rules. Props: `{ fields: FieldBoundary[]; plan?: PlanResponse }`. Each outline is evaluated separately; adjacent outlines are not dissolved.

## Algorithm and meaning

- Pure functions in `src/engine/pixelFit.ts`; no fetch, state, date, or planner imports.
- Area is recomputed from the outline, including subtracting holes, using a spherical cylindrical equal-area projection (`R=6371007.1809 m`). The contract's acreage is not blindly divided by an unrelated grid area. This is not a cadastral/survey area.
- Ratio = outline area / single pixel area. For angular grids use `R² Δlongitude (sin(north) − sin(south))` at the outline midpoint latitude. Thus acres per angular pixel change with latitude. The no-outline inventory uses the plan latitude or explicitly labelled 40° fallback.
- IMERG and POWER enumerate the native longitude/latitude lattice with their actual phase. For straight GeoJSON polygon edges in that coordinate space, the containment test is exact apart from floating-point boundary tolerance. Pixel-area ratios are representative at the midpoint, not a claim every intersecting angular cell has exactly that area.
- Projected products enumerate a **surrogate local equal-area square grid**, anchored at the outline bounding box southwest corner, at the documented spacing. Candidate square footprints are enumerated; full footprints are tested, not only sampled centres. **No native grid-phase/orientation alignment is claimed**. Counts can change with native phase and should be read as approximate geometric capacity. UTM scale, sinusoidal distortion, EASE spheroid/actual spacing, and Lambert distortion are not decoded here. Native raster transforms would be required for exact counts.
- All four corners must be inside the outer ring, none in a hole, and no outline/hole segment may enter the cell interior. This rejects concave notches and enclosed holes that a corner-only algorithm would miss. Boundary-touching cells are included within floating-point tolerance. No centre-only or floor(area-ratio) counts.
- **Field-scale**: at least **9 whole pixels**, an explicit demonstration setting, not a sourced agronomic criterion, QA score, minimum independent observations, or reliable-crop guarantee. **Mixed-edge**: ratio ≥1 but fewer than nine contained cells. **Regional-only**: ratio <1; SMAP, IMERG, POWER, Daymet and GRACE are always regional context regardless of geometrical count (conservative display policy).
- SSURGO is `not-raster`; GRACE is `support-area-only` and its count is unknown. Missing/unsupported geometry and computational limits remain unknown, not zero. Supported inputs are simple closed WGS84 Polygon rings, <85° absolute latitude, no antimeridian crossing, ≤10° extent. Up to 100,000 candidate cells are evaluated; self-intersecting polygons are outside the simple-ring contract.
- These counts do **not** intersect actual raster masks, cloud QA, acquisition coverage, or date availability. Geometry fit is not evidence delivery. CSB outlines are synthetic crop-sequence boundaries, not ownership/tax parcels. POWER is roughly 50 km weather: neighbouring fields can share it.
