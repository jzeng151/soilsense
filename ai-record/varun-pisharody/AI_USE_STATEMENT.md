# AI Use Statement (Kansas crop rotation pipeline, Varun Pisharody)

**Scope.** This statement covers only the `kansas-crop-rotation/` folder of this repository (Varun Pisharody's Kansas
crop rotation pipeline) and the published advice file it produces. It does not cover the rest of SoilSense.

**Tool.** Claude, an AI assistant made by Anthropic, used through the Claude app on Nov 14–15, 2026. Models: Claude
Fable 5.2 (`claude-fable-5-2`) and Claude Opus 5.5 (`claude-opus-5-5`); the logs note which entries used which.

**What the AI did.** Claude wrote essentially all of the code in `kansas-crop-rotation/scripts/` (each script says so in
its header). It designed the crop-rotation scoring method, fitted its heat coefficients, built the weekly refresh
(GitHub Actions to Cloudflare R2), wrote the handoff guides and the references list, and researched which NASA
datasets to use.

**What the team and Varun decided.** The project idea, the focus on Kansas, giving farmers ranked crop rotations,
scoring on more than water, and keeping NASA data at the centre.

**What Varun did and checked himself.** He ran the data downloads and database loads on his own computer, created and
controls all accounts and keys, chose between the options Claude offered, started the publishing runs, and reviewed
the outputs, charts and written explanations of the method. He did not independently re-derive the code or the
statistics; the re-checks described in the logs (including an independent re-implementation) were also done by Claude.

**Validation - what it is and is not.** The comparison with USDA NASS county yields is exploratory testing of the
weather scores only (`kansas-crop-rotation/reports/yield_validation.md`). It does not test economics, which the model
does not include, and it does not test rotation outcomes: no rotation was compared in the field. Much of the signal
comes from the 2022–23 drought.

**Sourced values versus modelling assumptions.**
- *Sourced:* weather and soil wetness (NASA POWER); county yields (USDA NASS); drought categories (U.S. Drought
  Monitor); the list of rotations per region (K-State publications); crop season dates (USDA NASS Agricultural
  Handbook 628, via K-State); the heat thresholds and flowering windows for corn, sorghum and wheat (K-State); the
  crop water-response factors and seasonal water needs (FAO). Sources are in
  `kansas-crop-rotation/reports/REFERENCES.md`.
- *Modelling assumptions (chosen by Claude or the team, not published values):* the soybean heat threshold and
  flowering window (set the same as corn); the double-crop soybean dates and water need; storing 25 % of off-season
  rain (picked from K-State's reported 20–30 % range) and its 230 mm cap; counting winter-dormancy rain at 25 %;
  halving a western summer crop that follows another summer crop (based on a K-State field result, applied as a
  fixed factor); grouping counties into nine approximate districts; and the 30 % / 50 % alert cut-offs. The script
  headers mark the assumptions.
- *Fitted:* the heat coefficients, fitted to the USDA yield data.
- No input data were generated by the AI.

**Credentials.** Claude was not given credentials to use, and none are in this record. Two exposures are recorded in
the logs: an Earthdata Login token was pasted into the chat once (part 1, entry 30), and a weak database password was
visible in a screenshot (part 2, entry 42). Claude did not use, store or copy either. Per the logs, Varun was advised
to revoke the pasted token and created a new one, and he replaced the password the same day.
